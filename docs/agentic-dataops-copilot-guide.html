P1 · Engineering Judgment

Engineering Decisions & Production Evidence

這個專案的重點不是讓 AI「更自主」，而是證明 AI reasoning 與 production authority 可以被工程化地分離。

Problem

LLM 的 hallucination、prompt injection 或錯誤 RCA，不能直接變成 production mutation。

Key Decision

Reasoning → Deterministic Policy → Separate Approval → Explicit Executor → Audit。任何一步不成立，就不能形成 production change。

Safety Boundary

Mutation executor registry 預設為空；AI 可以提出 action plan，但不會因模型輸出自行取得 authority。

DecisionBenefitTrade-off
Reasoning / execution separation模型錯誤不會直接變成 production change不是 full-auto remediation，處置速度較慢
Deterministic Policy EngineRisk、RBAC、allow-list 不依賴 probabilistic modelPolicy 需要持續維護與 change control
Human Approval + SoD高風險 action 有獨立責任人與 audit trail增加 approval latency 與 operational friction
Failure ScenarioEngineering ResponseEvidence
Hallucinated / malformed action plan仍需 deterministic policy 與 approval；不能直接執行test_governance.py
Approver reject / timeoutAction 不進 execution，pending/rejected 狀態保留policy.py
Execution / audit failureOutcome 必須形成 audit event，不把 partial failure 當成功audit.py
Evidence source unavailable降低 RCA confidence，恢復 evidence 後重新 triage；human 保留最終判斷test_integrations.py
Interview signal：真正的 Agentic DataOps 不是「讓 LLM 執行 kubectl」，而是把 reasoning、authority、approval、executor 與 accountability 分層。
01 · Positioning

作品集定位：Reasoning & Operations / AI 推理與 DataOps 維運

此 Repository 專注於 incident reasoning、evidence correlation、root-cause analysis、recommendation、policy、approval 與 controlled action。它不是 Knowledge AI Platform、不是 canonical MCP tool server，也不是 model gateway。

E

G

Governance

Policy、Approval、SoD、Audit 把 AI recommendation 與 production action 分離。

14 · Interview Q&A

常見追問

為什麼不直接讓 Agent 呼叫 kubectl / SQL？

Model output 不應等於 execution authority；recommendation、plan、policy、approval、executor 必須分離。

Multi-Agent 的價值？

重點是責任分離與可測試性，不是 Agent 數量。reviewer 尤其用來把高風險輸出導向 governance。

RAG 為什麼用 deterministic hashing embedding？

為了 offline/CI 可重現。Embedder 與 VectorStore 已抽象化，production 可替換真正 embedding/vector DB。

Audit hash chain 等於不可竄改嗎？

不是。v0.5 是 within-process tamper-evident；durable/immutable audit 要到 persistent store + external sink。

Header identity 安全嗎？

它只是 reference propagation。Production 應由 OIDC/JWT-aware gateway 或 proxy 驗證，再重建 trusted identity context。
